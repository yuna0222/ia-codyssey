# Week01 - 미션 컴퓨터 복구 및 로그 분석


## 1. 문제 정의

화성 기지 사고 이후, 미션 컴퓨터의 소프트웨어가 모두 사라진 상태에서  
남아있는 로그 파일(`mission_computer_main.log`)을 기반으로  
사고 원인을 파악해야 한다.

로그를 읽고 분석할 수 있는 환경조차 없는 상황이기 때문에  
Python을 이용해 직접 로그 분석 프로그램을 구현하는 것이 목표이다.
![img.png](/images/img-week01.png)

## 2. 목표

- Python 개발 환경 구성
- 로그 파일 읽기 및 출력
- 파일 처리 중 발생할 수 있는 예외 처리
- 로그 데이터를 기반으로 사고 원인 분석
- 분석 결과를 Markdown 보고서로 작성


## 3. 구현 내용

### 3.1 개발 환경 설정
- Python 3.x 설치
- 실행 확인 (`Hello Mars` 출력)

### 3.2 로그 파일 읽기
- `mission_computer_main.log` 파일을 읽어 전체 출력
- `with open()`을 사용한 파일 처리

### 3.3 예외 처리
- 파일이 없을 경우 (`FileNotFoundError`)
- 권한 문제 (`PermissionError`)
- 인코딩 문제 (`UnicodeDecodeError`)
- 기타 파일 시스템 오류 (`OSError`)

### 3.4 로그 데이터 파싱
- CSV 형태의 로그를 파싱하여 구조화 (dict 형태)
- timestamp / event / message 분리 + score

### 3.5 위험도 분석
- 키워드 기반 점수화 방식 적용
- 위험 로그 필터링 및 사고 원인 추정

### 3.6 결과 출력 및 저장
- 전체 로그 출력
- 위험 로그 별도 저장
- 시간 역순 로그 저장
- Markdown 보고서 생성

## 7. 느낀 점
- 단순 출력보다 데이터 구조화가 더 중요하다
- 키워드 점수로도 분석이 가능하다
- 함수 분리가 코드 가독성에 큰 영향을 준다
