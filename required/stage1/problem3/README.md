# Week02 - 화성 기지 위험 물질 분류 및 데이터 처리


## 1. 문제 정의

화성 기지 사고 이후, 로그 분석을 통해 사고 원인이 단순 화재가 아닌
인화성 물질로 인한 폭발일 가능성이 높다는 결론에 도달하였다.

현재 기지에는 건설 자재와 다양한 화학 물질이 혼재되어 있으며,
이 중 인화성이 높은 물질을 선별하여 기지 외부로 격리하는 작업이 필요하다.

이를 위해 제공된 Mars_Base_Inventory_List.csv 파일을 기반으로
물질 데이터를 분석하고, 위험 물질을 분류하는 프로그램을 구현한다.

## 2. 목표
- CSV 파일을 읽어 데이터 구조로 변환
- 물질 정보를 리스트(List) + 딕셔너리(Dictionary) 형태로 관리
- 인화성 기준으로 데이터 정렬
- 특정 기준(0.7 이상)의 위험 물질 필터링
- 필터링된 결과를 CSV 파일로 저장
- 이진 파일(Binary) 형태로 데이터 저장 및 복원
- 텍스트 파일과 이진 파일의 차이 이해


##  3. 구현 내용
### 3.1 CSV 파일 읽기 및 출력
- with open()을 사용하여 CSV 파일 읽기
- 각 줄을 리스트 형태로 처리

### 3.2 CSV → List[Dict] 변환
- split(',')을 활용하여 데이터 분리
- 첫 줄(Header)을 기준으로 key 생성
- zip()을 활용하여 key-value 매핑
- 최종적으로 리스트 안에 딕셔너리 형태로 저장

### 3.3 데이터 정렬
- sorted() 함수 사용
- lambda를 활용하여 flammability 기준 정렬

### 3.4 위험 물질 필터링
- 리스트 컴프리헨션 사용
- `[r for r in records if r['flammability'] >= 0.7]`
- 인화성 지수가 높은 물질만 추출

### 3.5 CSV 파일 저장
- write()를 사용하여 파일 출력
- dict.get()을 활용하여 키가 없는 경우에도 안전하게 처리

### 3.6 이진 파일 저장 및 복원
- Python 객체를 그대로 저장
- 저장된 데이터를 다시 읽어 출력
- CSV 대비 빠른 처리 속도 확인



##  4. 텍스트 파일 vs 이진 파일 비교
이번 과제를 통해 데이터를 두 가지 방식으로 저장하고 비교하였다.

### 📌 텍스트 파일 (.csv)
- 사람이 읽을 수 있는 문자열 기반 파일
- 엑셀, 메모장 등에서 바로 확인 가능
- 다양한 언어에서 사용 가능
- 데이터가 많을 경우 처리 속도가 느림
- 숫자 데이터도 문자열로 저장됨

### 📌 이진 파일 (.bin)
- 데이터를 바이트 형태로 저장
- Python 객체를 그대로 저장/복원 가능
- 처리 속도가 빠르고 파일 크기가 작음
- 사람이 직접 읽을 수 없음
- Python 환경에 종속적


### 📊 비교 요약
| 구분     | 텍스트 파일 (.csv) | 이진 파일 (.bin) |
| ------ | ------------- | ------------ |
| 저장 방식  | 문자열           | 바이트          |
| 가독성    | 높음            | 낮음           |
| 처리 속도  | 느림            | 빠름           |
| 데이터 타입 | 변환 필요         | 유지           |
| 호환성    | 높음            | 낮음           |

### 💡 결론
텍스트 파일은 범용성과 가독성이 뛰어나고,
이진 파일은 성능과 데이터 보존 측면에서 유리하다.

상황에 따라 적절한 파일 형식을 선택하는 것이 중요하다.

## 5. 느낀 점
- CSV 데이터를 단순히 출력하는 것이 아니라 구조화하는 과정이 중요함을 느꼈다
- zip()과 dict를 활용하면 데이터 매핑을 효율적으로 처리할 수 있다
- 리스트 컴프리헨션을 활용하면 필터링 로직을 간결하게 표현할 수 있다
- 파일 저장 방식에 따라 성능과 활용도가 크게 달라진다는 것을 이해했다
- 데이터 처리 과정에서 예외 처리와 안정성 확보가 매우 중요하다
